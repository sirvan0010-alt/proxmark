## 3. BWM protocol — PASS / PROTOCOL VERIFIED

- Request/response/broadcast framing exists.
- CRC scope is documented as magic + command ID + length + payload.
- CRC provenance points to the specified `Proxmark5_BWM_esp32` source/commit.
- Command definitions are preserved as an upstream snapshot.
- Stream parser tests cover fragmentation, multiple frames, garbage, bad CRC, invalid length and resynchronisation.

**Boundary:** this is protocol/source verification, not physical PM5 verification. Payload layouts remain below high confidence until evidence confirms them.

## 4. Read-only adapter — PASS

During this audit an actual design weakness was found and fixed: the public `QueryAsync` previously accepted any `BwmCommandCode` despite the adapter being documented as read-only.

It now explicitly allow-lists only:

- `GetVersionInfo`
- `GetDeviceModel`
- `GetAppCompileDatetime`
- `GetSysFreeHeap`
- `GetSysBaseMacAddr`

Mutating commands are rejected **before transport invocation**. Cancellation is no longer swallowed as a generic transport error. Tests cover both behaviours.
